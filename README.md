## Overview

Many banking operations teams rely only on past data and lack accessible forecasting tools.
This dashboard transforms historical financial time-series data into actionable predictions —
giving branch managers and risk officers honest signals to act on, not just backward-looking reports.

It generates **1–6 week forecasts with confidence intervals**, detects anomalies with early
warnings, compares what-if scenarios side by side, and delivers plain-English AI briefings
powered by **Google Gemini** — all in a lightweight, transparent, and fast interface.

**Intended users:** Branch managers, risk officers, and operations analysts at NatWest who
need to anticipate trends in transaction volumes, loan defaults, and customer metrics without
needing data science expertise.

## Features

All features listed below are implemented and working in the current codebase.

- **Short-term forecasting** — 1–6 week horizon with Prophet and AutoETS models
- **Confidence bands** — 80% and 95% prediction intervals shown as shaded chart areas
- **Baseline comparison** — naive and moving-average baselines with MAPE/RMSE accuracy panel
- **Anomaly detection** — Z-score and IQR flagging with Warning/Critical severity badges
- **AI-generated explanations** — Gemini explains each anomaly and suggests next steps
- **Scenario builder** — adjust growth rate, remove outliers, apply seasonal boosts
- **Scenario comparison** — side-by-side chart of baseline vs adjusted forecast with diff summary
- **AI briefing** — plain-English streaming summary generated by Google Gemini
- **Data quality pre-flight** — PASS / WARN / FAIL checks before any model runs
- **Transparency panel** — model used, training range, accuracy metrics, detected patterns
- **CSV upload** — drag-and-drop with column auto-detection and 5-row preview
- **6 default banking datasets** — loads instantly with no upload required (demo-ready)
- **Export** — download forecast as CSV and chart as PNG

## Local Development — Install and Run

### Prerequisites

- Node.js 18 or higher — [nodejs.org](https://nodejs.org)
- Python 3.11 or higher — [python.org](https://python.org)
- A Google Gemini API key — [aistudio.google.com](https://aistudio.google.com) (free, no card required)

---

### 1. Clone the repository

```bash
git clone https://github.com/The-Fermits/natwest-forecasting.git
cd natwest-forecasting
```

---

### 2. Set up and run the backend

```bash
# Navigate to backend
cd backend

# Create and activate a virtual environment
python -m venv venv
source venv/bin/activate        # macOS / Linux
# venv\Scripts\activate         # Windows

# Install all dependencies
pip install -r requirements.txt

# Create your environment file from the example
cp .env.example .env
```

Now open `.env` in any text editor and set your Gemini API key:

```
GEMINI_API_KEY=your_gemini_api_key_here
FRONTEND_URL=http://localhost:3000
```

```bash
# Generate the 6 default banking datasets
python data/generate_seed_data.py

# Start the backend server
uvicorn main:app --reload --port 8000
```

Verify the backend is running: open http://localhost:8000/health in your browser.
You should see: `{"status": "ok", "model_ready": true}`

---

### 3. Set up and run the frontend

Open a new terminal tab:

```bash
# Navigate to frontend
cd frontend

# Install dependencies
npm install

# Create your environment file from the example
cp .env.example .env.local
```

Open `.env.local` and set:

```
NEXT_PUBLIC_API_URL=http://localhost:8000
```

```bash
# Start the frontend dev server
npm run dev
```

Open http://localhost:3000 in your browser. The dashboard loads with the default
transaction volume dataset ready to forecast.

---

### 4. Run the tests

```bash
cd backend
pytest tests/ -v
```

Expected output: all tests pass. Tests cover ingestion, forecasting, anomaly detection,
baseline models, and data quality checks.

## Usage

### Default datasets (no upload needed)

1. Open https://natwest-forecasting.vercel.app
2. Select a metric from the dropdown (e.g. "Transaction Volume — North Region")
3. Choose a forecast horizon (1–6 weeks) using the slider
4. Click **Run Forecast**
5. View the chart with confidence bands, anomaly markers, and baseline comparison
6. Read the AI briefing card for a plain-English summary
7. Open the Scenario Builder to test what-if adjustments
8. Export results as CSV or PNG using the Export buttons

### Upload your own CSV

1. Click the **Upload CSV** tab
2. Drag and drop a CSV file with a date column and a numeric value column
3. The system detects columns automatically and shows a 5-row preview
4. Run the same forecast pipeline on your own data

**Accepted CSV format:**
```csv
date,value
2023-01-02,12450
2023-01-09,11980
2023-01-16,13200
...
```
Minimum 12 rows required. Date column can be named: `date`, `week`, `period`, `timestamp`.
Value column can be named: `value`, `amount`, `count`, `volume`, or any numeric column.

## Technical Depth

### Why Prophet + AutoETS instead of a single model?

We use a high-availability model selection architecture:
- **Prophet** is our premium model for seasonal data.
- **AutoETS** (from `statsforecast`) is our high-robustness fallback. On Windows environments where C++ compilers are missing, the backend automatically detects the failure and seamlessly pivots to AutoETS. This ensures zero downtime and reliable forecasts regardless of the hosting environment.

### Why show confidence bands?

Overconfident point forecasts cause poor banking decisions. Displaying 80% and 95% prediction intervals forces honest communication of uncertainty — a core requirement of the hackathon problem statement.

### Why Z-score AND IQR for anomaly detection?

Z-score works well for normally distributed data but can miss anomalies in skewed series. IQR is robust to skew. Running both ensures we catch outliers in diverse banking datasets.
